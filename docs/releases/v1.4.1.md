# v1.4.1 — Review Fixes

!!! warning "Security release — October 2026"
    Fixes the findings of the 1.4.0 architecture, security and performance
    review. Several defaults changed on purpose; read
    [Deliberate behavior changes](#deliberate-behavior-changes) before upgrading.

## Security

| Finding | What changed |
|---|---|
| Unrouted endpoints skipped auth | `/health*`, `/metrics` and `/graphql` now go through the full middleware chain. JWT, Basic, API key, sessions, CSRF and rate limiting run first; the endpoint answers last. A path nothing owns still returns 404 before auth, so route existence does not leak. Add probe paths to `skip_paths` if they must stay public. |
| Rate limit trusted `X-Forwarded-For` | The accepted socket address is now stored on the request (`request.remote_addr`). `request.client_ip()`, `is_secure()`, `host()` and the rate limiter use the TCP peer unless the peer is listed in `App.set_trusted_proxies([...])` (IPs or CIDRs). Behind a trusted proxy the client is the right-most `X-Forwarded-For` hop that is not itself trusted. |
| `RateLimitConfig.key_by` ignored | Honoured: `"ip"` (default), `"user"` (`context["user"]["id"]` or the JWT `sub`, else IP), `"api_key"` (`X-API-Key`), `"header:<name>"`. Unknown values raise `ValueError`. |
| Cache mixed users | Requests with `Authorization` or `Cookie` are not cached unless `enable_caching(cache_authenticated=True)`, which adds those headers to the key. Responses with `Set-Cookie`, `Cache-Control: private/no-store/no-cache` or `Vary: *` are not stored. Only 200/203/204 are cached. The cache no longer adds `Cache-Control: max-age=…`. The store is capped (`max_entries`, default 10 000) and bodies over 1 MiB are not stored. |
| Sessions never saved updates | New `request.session` object shared with the middleware: `get`, `set`, `s[k]`, `s[k] = v`, `del s[k]`, `pop`, `keys`, `clear`, `regenerate()`, `destroy()`, `is_new`. Changes are persisted at the end of the request. A session gains a new id automatically when it first receives a login key (`user_id`, `user`, `username`, `auth`, `authenticated`). All `SessionConfig` cookie fields are applied. |
| One `Set-Cookie` per response | Responses keep repeatable headers separately; session and CSRF cookies are both sent. |
| CSRF | The token is read from the header or from a `_csrf` field in a urlencoded or multipart body. The query string is no longer accepted. With an established session the token is stored in it and must match. Signed tokens must also match the cookie, and future timestamps are rejected. `TRACE` is no longer a safe method. The cookie is reused instead of rotated on every page view. |
| Error details exposed by default | The Rust default is now "hide". `app.run()` exposes details only for an explicit `env="development"`, `--debug`, `CELLO_ENV=development`, or an interactive terminal. Windows workers receive the parent's resolved host, port, debug and logging settings. |
| Credentialed CORS reflected any origin | `allow_credentials()` with "any origin" keeps `Access-Control-Allow-Origin: *` and omits `Access-Control-Allow-Credentials`. `Mirror` never reflects `null`. `*.example.com` matches subdomains only (not `notexample.com`). Preflight max-age default is 600 s. `Vary` values are merged, not overwritten. |
| Auth comparisons | Basic Auth (dict form) and API-key maps compare every entry in constant time via SHA-256 digests. JWT failures return one generic message. `JwtConfig(issuer=…, audience=…)` is now enforced. |
| Header logging | `LoggingMiddleware.with_headers()` redacts `Authorization`, `Cookie`, `X-API-Key` and similar. |
| GraphQL defaults | Playground and introspection are off unless enabled in `GraphQLConfig`. |
| SSE comment injection | `sse_comment` strips CR/LF. |
| OpenAPI handler code | The Rust `enable_openapi` no longer splices the title into evaluated source; the title is passed as a value and HTML-escaped. |

## Bugs

- **Static files:** hidden paths are now checked per path segment (`.env`, `.git/…` refused; `app.js` served). The mount needs a `/` boundary (`/static` no longer claims `/static-other`). Precompressed `.br`/`.gz` siblings are canonicalized and re-checked against the root. Directory listings escape file names. SVGs carry a sandboxing CSP. `Last-Modified` is a real HTTP date. Files are read with `tokio::fs` off the server thread, with a size cap (`max_file_size`, default 256 MiB).
- **Early responses skipped `after` hooks:** a middleware stop or error, guard rejection, cache HIT and unrouted endpoint now get all sync `after` hooks, so 401/429/403 and cached responses carry security headers, CORS headers and cookies. The circuit breaker ignores these responses (they are not backend outcomes).
- **Compression:** `Content-Length` is never stale (the server derives framing from the body), `gzip;q=0` is honoured, already-encoded bodies are not re-compressed, `Vary` is merged.
- **Limits and timeouts:** every `LimitsConfig` field is enforced (`max_header_size` → 431, `max_connections`, `max_requests_per_connection` → `Connection: close`). `TimeoutConfig.idle_timeout` closes idle keep-alive connections. The connection-limit check no longer races. Header-read timeout defaults to 30 s.
- **Process model:** with `workers=N` the parent is a supervisor and exactly N processes serve. Each forked worker gets a fresh database pool, Redis connection and I/O runtime. Development runs default to one worker.
- **WebSocket:** `@app.websocket(path)` handlers are now served (HTTP/1.1 upgrade, auth and rate limiting run on the upgrade request). Handlers are sync functions using `ws.recv(timeout=None)` (returns `None` when the client closes), `ws.send_text`, `ws.send_binary`, `ws.close`, `ws.request`. Read a message's payload with `msg.content` — `msg.text` is the `WebSocketMessage.text(...)` constructor.
- Duplicate request headers are joined instead of the last one winning.
- Postgres row counts above `i64::MAX` no longer wrap negative.
- A failed JSON serialization returns 500 instead of an empty 200.
- Release builds have `overflow-checks = true`; the u64 subtraction sites on the request path use saturating arithmetic.
- Hot reload skips hidden, cache, build and dependency directories.

- Python guards (`app.add_guard`) raising `UnauthorizedError` / `ForbiddenError` now answer 401 / 403 with their message; previously every rejection was a 500 that echoed the exception text. Other guard exceptions return a generic 500 and are logged.
- Follow-ups from an independent review of these fixes: the cache never stores a response that wrote the session or issued a fresh CSRF token; WebSocket upgrades run `app.add_guard` guards; signed CSRF tokens held in a session are re-issued after `max_age`; logging in as a different user regenerates the session id; HEAD keeps `Content-Length`; WebSocket sends are back-pressured (bounded queue); `ws.recv(timeout=inf)` is safe; live WebSockets count toward `max_connections`.

## Performance

- `request.json()` makes one copy of the body instead of two.
- Session, rate-limit and cache stores are bounded and swept periodically.
- Static file reads moved off the accept/parse thread.

Paired benchmark (`benchmarks/orm/paired.py`, both builds on Python 3.12.3,
simultaneous servers, wrk -t2 -c32 -d5s, ABBA rounds), 1.4.1 vs 1.4.0:

| endpoint | delta |
|---|---:|
| `control` (trivial JSON route) | about −5% |
| `orm_list` | −3% (within noise) |
| `validate` | +3% to +8% (within noise) |

The remaining cost on trivial routes is the new default 30 s header-read timeout
(the Slowloris guard): with it disabled the control delta is −3%, inside run-to-run
noise. Re-enabled overflow checks measured no cost. Per-connection bookkeeping for
`max_requests_per_connection` / `idle_timeout` exists only when one is configured (the in-flight/last-active part only with `idle_timeout`).
To trade the guard for the last few percent behind a proxy that already enforces
header timeouts: `app.set_timeouts(TimeoutConfig(read_header=0, read_body=0, handler=0, idle=0))`.

Second review pass, new bounded defaults (R8): one build, two servers run at the
same time, one configured with the previous defaults (100 MB body, unbounded
head and requests per connection, no body or handler timeout). wrk -t2 -c32 -d5s,
10 alternating rounds, trivial JSON route: **32 695 vs 32 616 rps (−0.2%)**, with
each side ahead in 5 of the 10 pairs. Measured one by one, the head cap is free
(+1.4%), the handler timer −0.8%, the per-connection request cap −0.9% and an idle
watchdog −1.8%. The idle watchdog stays opt-in, because the header-read timeout
already closes silent keep-alive connections. It now runs as its own task, and
its per-request bookkeeping exists only when it is configured. With it on by
default, the first measurement was −6.2%.

## Second review pass

A follow-up review of these fixes (findings N1–N3, R1–R8) was checked against
the code; every finding held and is fixed here. Pinned by
`tests/test_review_fixes_2.py`.

| Finding | What changed |
|---|---|
| N1 WebSocket inbound queue unbounded | Inbound messages are charged against a 4 MiB budget per socket (plus 64 bytes each). When the handler falls behind, the connection stops reading the socket, so TCP pushes back on the client. One message up to the 16 MiB limit is still accepted at a time. |
| N2 `async def` WebSocket handlers held a pool thread | They run on the application's persistent event loop and hold no thread while they wait. Use the awaitable methods `await ws.arecv(timeout=None)`, `await ws.asend(msg)`, `await ws.asend_text(...)`, `await ws.asend_binary(...)`. The blocking `recv`/`send*` raise `RuntimeError` on an event loop thread instead of stalling it. `def` handlers still run on the blocking pool. |
| N3 No Origin check on the upgrade | A browser handshake (one with `Origin`) must be same-origin (the `Origin` authority equals `Host`, or `X-Forwarded-Host` behind a trusted proxy) or listed in `@app.websocket(path, allowed_origins=[...])` (`["*"]` = any). Otherwise `403`. Clients that send no `Origin` are not browsers and are unaffected. |
| R1 `workers > 1` split sessions and rate limits | `App.run` refuses `workers > 1` when sessions or rate limiting are enabled (both keep state in process memory), naming the problem. Pass `allow_per_worker_state=True` (or `CELLO_ALLOW_PER_WORKER_STATE=1`) to accept per-worker state. A defaulted worker count (production, no `workers=`) falls back to 1 with a warning. A per-worker response cache only warns. |
| R2 GraphQL executor was a substring scan | Queries are parsed with a GraphQL parser (`async-graphql-parser`). The operation type, `operationName`, variables (with defaults and required checks), aliases, fragments, inline fragments and `@skip`/`@include` come from the document. `max_depth` and `max_complexity` are enforced (fragments expanded, cycles rejected, a hard cap of 100 000 selections, documents capped at 100 KB and 128 levels of brackets). Introspection is detected anywhere in the document. Rejected documents return `400`. `App.enable_graphql(config, schema=...)` now serves Python resolvers from `cello.graphql.Schema` / `GraphQL` with the same parser and limits. |
| R4 Trusted proxies were process-global; `X-Real-IP` unchecked | The list belongs to each `App` (changes apply to new connections). `X-Real-IP` is ignored unless `set_trusted_proxies(..., trust_x_real_ip=True)`. |
| R5 CSRF unbound before a session existed | The default cookie is `__Host-csrf` (host-only, `Secure`, `Path=/`), so a sibling subdomain cannot plant a token. The token is written into the session on the request that creates it (for example a login POST that passed the double-submit check), so every later request is checked against the session. Anonymous visitors still get no session. |
| R6 Rotation watched five keys; the session map was unbounded | The default login-key list adds `userid`, `uid`, `account_id`, `email`, `is_authenticated`, `logged_in`, `role`, `roles`; `SessionConfig(auth_keys=[...])` replaces it. The in-memory store holds at most `SessionConfig.max_sessions` (default 100 000) and evicts the least recently used sixteenth when full (O(n) partition, not a sort). A session over `max_session_size` (default 64 KiB serialized) raises `ValueError` at the write. |
| R7 Static files were one buffer; index name not re-checked | Deferred file bodies over 1 MiB are streamed in 64 KiB chunks with an exact `Content-Length`; smaller ones are read whole so compression, ETag and caching still see them. The ETag, cache and compression middleware leave a streamed body alone. The configured index file is canonicalized and checked against the root. |
| R8 Safe limits were opt-in | Server defaults now equal `LimitsConfig()`: 10 MiB body, 16 KiB request head (`LimitsConfig` default raised from 8 KiB), 10 000 connections, 1 000 requests per connection. Body-read and handler timeouts default to 30 s. `0` still disables any of them. (The idle watchdog stays opt-in: the 30 s header-read timeout already closes a keep-alive connection that sends nothing.) |
| Cache eviction sorted under the write lock | It partitions around the cut instead (O(n)). |
| `key_by="header:..."` stored raw header values | The header is stored as a 128-bit SHA-256 digest. Once a store holds 100 000 keys (checked every 256 requests, after a sweep), new requests share their client IP's bucket. |

Found while checking R7 (not in the review):

- **Handler-returned `Response` objects lost data.** They went through JSON, with
  the body as a UTF-8 string, so a binary body arrived empty. `Response.sendfile`
  and `file_range` sent an empty body plus an `X-Sendfile-Path` header that leaked
  the server path, and `append_header` values (repeated `Set-Cookie`) were
  dropped. A `Response` is now passed through unchanged, and file bodies are
  read (or streamed) like static files.
- **`cello.graphql.GraphQL.execute` ran every registered query and every mutation**
  on each call, whatever the document asked for (and passed the variables to every
  mutation). It now resolves only the operation's selected root fields with their
  arguments and trims results to the sub-selection. `createItem` finds a resolver
  named `createItem` or `create_item`.
- The built-in endpoint read the operation name from `operation_name`; the
  GraphQL-over-HTTP key `operationName` is accepted.

## Deliberate behavior changes

- `app.run()` with no `env`/`debug`, no TTY (container, service manager, CI): 500 responses are generic. Use `env="development"` or `debug=True` to see details.
- GraphQL playground and introspection are off by default.
- `X-Forwarded-*` / `X-Real-IP` are ignored unless the peer is in `App.set_trusted_proxies(...)`.
- The cache skips requests with `Authorization`/`Cookie` and no longer sets `Cache-Control`.
- A session nothing wrote to is neither stored nor sent as a cookie. A login regenerates the session id.
- CSRF tokens in the query string are rejected; `TRACE` requires a token.
- CORS: credentials are never granted with a wildcard origin; preflight max-age is 600 s.
- Header-read timeout is on by default (30 s); it also closes idle keep-alive connections.
- `workers=N` runs N serving processes plus a non-serving supervisor (was N+1 serving).
- `/health`, `/metrics` and `/graphql` require authentication when auth middleware is enabled.
- Second review pass:
  - Default body cap 10 MiB (was 100 MiB). Default head cap 16 KiB. 30 s body-read and handler timeouts. 1 000 requests per connection. Raise them with `set_limits` / `set_timeouts` (`0` disables).
  - `workers > 1` with sessions or rate limiting raises unless `allow_per_worker_state=True`. A defaulted worker count falls back to 1.
  - Browser WebSocket handshakes from another origin get `403` unless allowed.
  - `async def` WebSocket handlers must use `arecv` / `asend*`.
  - The CSRF cookie is `__Host-csrf` (was `_csrf`).
  - `X-Real-IP` needs `trust_x_real_ip=True`. Trusted proxies are per app.
  - `GraphQL.execute` resolves only the selected fields, passing field arguments. Mutations no longer receive the variables dict as keyword arguments.
  - GraphQL documents rejected by the parser or the limits answer `400`.

## Not done / known limits

- `TimeoutConfig.write_timeout` is accepted but not enforced.
- `Http2Config`, `Http3Config` and `TlsConfig` are configuration records only; the server speaks HTTP/1.1. Terminate TLS/HTTP/2 at a proxy and list it in `set_trusted_proxies`.
- The built-in GraphQL endpoint resolves root fields only. There is no type system, so no schema validation or nested resolvers. Sub-selections trim `dict`/object results in the Python engine. Subscriptions are not served over HTTP.
- Request bodies are still collected (up to the body cap) before the handler runs. Only file responses are streamed.
- Sessions, rate limits and the response cache are per process; there is no shared (Redis) backend for them yet. Hence the `workers` guard.
- A `def` WebSocket handler still holds a blocking-pool thread for the life of the socket.
- Dependency refresh (PyO3 0.20, reqwest 0.11, rustls 0.22, OpenTelemetry) and `cargo audit` were out of scope: they need networked crate upgrades.
- Six Rust unit tests fail on the unchanged 1.4.0 tree as well (`dependency`, `cache` expiry, `exception_handler`, `prometheus` encode, `multipart_streaming`, `parse_range_header`); they are unrelated to these fixes.
